# 03. 전략 판단 — 무엇이 기여이고 무엇이 아닌가

> 이 문서에 동의하지 않으면 나머지 계획이 성립하지 않는다. 반대 의견이 있다면 여기서 다투고 넘어갈 것.

## 1. 결론 3줄

1. **응급도 추정기를 만들지 마라.** 가상 환자에게서 추정하는 것은 순환이고, 실제 사람에게서 추정하는 것은 DARPA급 문제다.
2. **불확실성의 표현이 기여다.** 응급대응 AR 논문 90편에 트리아지 전용 인터페이스 연구가 없고, 존재하는 AR 트리아지 시스템 2편은 분류 정확도를 결과로 보고하지 않았다.
3. **dwell 시간 비교는 기여가 아니다.** 2025년에 이미 동적 dwell 메타분석이 나왔다.

## 2. 왜 추정기를 만들면 안 되는가

### 2a. 가상 환자 경로 — 순환 논증

환자가 Unity 모델이면 상태를 우리가 저작한다. 그 상태를 읽어 라벨을 출력하는 것은 추정이 아니라 조회다. 리뷰어는 이것을 즉시 알아본다. *"You authored the labels and your system read them back"* 은 방어가 불가능하다.

### 2b. 실제 영상 경로 — 문제 자체가 미해결

| 근거 | 수치 |
|---|---|
| rPPG, 심박 상승 시 | 8개 방법 중 **5개가 유의하게 붕괴**. PhysNet Δmedian −13.55 |
| rPPG, 피부톤 편향 | 고전 기법 MAE **5.2 → 14.1 bpm**, DL **6.0 → 9.5 bpm** (Monk 4–10은 데이터셋의 25% 미만) |
| 카메라 SpO₂ | 캘리브레이션 의존. 5프레임 RMSE 5.85%, 270프레임 3.24%. 교차 데이터셋 실패 |
| standoff 운동성 분류 (CMU, LiDAR+IR+RGB) | 실제 필드 데이터 **15명 중 10명 정답, 오탐 3건** — 그것도 안전 임계 방향(Absent→Normal) |
| 보행 이상(절뚝임) 검출 | 정상 97%, **절뚝임 70%** |
| 드론 반자동 트리아지 (최상 사례) | 89% 정확도, 그러나 건강한 지원자 15명·30회 측정 |

핵심: **트리아지 환자는 정의상 빈맥이고, 움직이고, 조명이 나쁘고, 누워 있다.** 문헌의 오차 막대는 전부 평온하게 앉아 있는 60~80bpm 지원자에게서 측정됐다. 이 간극은 학생 프로젝트가 메울 수 있는 크기가 아니다.

**그래서 올바른 대응은 "안 한다"가 아니라 "왜 못 하는지를 근거와 함께 쓰고, 그 제약을 연구 설계로 전환한다"이다.**

### 2c. 우리 하드웨어가 보는 것

웹캠은 **구조자**를 본다. HoloLens 2도 착용자의 손·시선을 본다. 어느 쪽도 환자를 향한 센싱이 아니다. 시스템 구조상 응급도 추정의 자리가 없다.

## 3. 진짜 공백은 어디에 있는가

### 근거가 되는 문헌 사실

| 출처 | 발견 |
|---|---|
| AR for First Responders 스코핑 리뷰 (arXiv 2506.09236, 90편) | **트리아지 전용 인터페이스 연구 라인이 없음.** off-FOV 안내 커버리지 얇음. 상황인식(SA)이 체계적으로 평가된 적 없음. 다수가 개념/저충실도 프로토타입 |
| ARTTS (HFES 2022) | 머리 착용 트리아지 도구 세트 — **UX 설계 방법론 논문, 성능 평가 없음** |
| 적응형 AR 트리아지 훈련 (HFES 2024, HoloLens 2, N=15) | 사후 퀴즈 +33%, 인지부하 보고 — **학습 지표이지 트리아지 판단 지표가 아님** |
| XR EMS 체계적 리뷰 (2025, 19편) | 19편 중 10편(53%)이 MCI 트리아지. **8편이 윤리 승인 문서 결여** |

즉, AR 트리아지 시스템은 존재하지만 **"이 인터페이스를 쓰면 분류가 더 정확해지는가"를 측정한 논문이 없다.** 이것이 인용 가능한 공백이다.

### 인접 문헌은 성숙해 있다

불확실성 시각화·자동화 편향·적정 의존(appropriate reliance) 연구는 이미 두텁다. 그런데 **공간 AR 트리아지에 적용된 적이 없다.** 성숙한 이론 + 미적용 도메인 = 학생 규모에서 방어 가능한 기여.

## 4. 채택한 프레이밍

> **Reliability-aware urgency overlay: 불완전한 응급도 추정을 AR HUD에서 어떻게 표현해야 하는가?**

### 왜 이것인가

| 기준 | 평가 |
|---|---|
| 기존 프로토타입 재사용률 | **약 80%** — 장비가 이미 있다 |
| 종속변수의 기성성 | 트리아지 문헌이 정확도·과/저분류·시간을 이미 표준화 |
| 가상 환자 문제 | **한계가 아니라 올바른 설계로 전환됨** — 정확도 조작은 실제 시스템으로 불가능 |
| 신뢰도 수준의 정당화 | 100/85/70%를 임의값이 아닌 실제 시스템 수치로 인용 가능 (89%, 82.8%, 10/15) |
| 6개월 실현성 | 높음 |

### 예상 리뷰어 공격과 방어

> *"추정기를 Wizard-of-Oz했으니 트리아지 옷을 입은 불확실성 시각화 연구일 뿐이다."*

**방어:** 제목에서 인정한다. 기여는 *표현*이고, 시뮬레이션된 정확도 수준은 발명한 것이 아니라 실제 시스템에서 인용한 것이다. 그리고 실제 시스템은 정확도를 원하는 값으로 맞출 수 없으므로 이 설계가 오히려 우월하다.

## 5. 대안 프레이밍 (2순위 이하)

기록으로 남긴다. 1순위가 파일럿에서 무너질 경우의 대비책.

### 2순위 — FOV 예산 하의 트리아지: 화면 밖 대상 안내
화면 밖 대상마다 **응급도가 다를 때** 안내 단서가 탐색 *순서*를 어떻게 바꾸는가. 종속변수는 탐색 순서 최적성, 최우선 환자까지의 시간, 누락률. 데스크톱에서 FOV 폭을 조작할 수 있고, HL2로 가면 52°가 실제 제약이 되어 자연스럽게 연결된다.
**리스크:** "out-of-view 시각화는 이미 해결됐다"

### 3순위 — 움직임만으로 하는 트리아지: standoff CV가 실제로 볼 수 있는 것만 제공
실제 standoff 시스템이 전달 가능한 단서(움직임/무반응, 보행 가능, 자세)만 주고 전체 정보 대비 판단 정확도가 얼마나 떨어지는지 측정. **요구사항 결과**를 산출한다 — 로보틱스 쪽에 "센싱 충실도를 어디까지 사는 게 값어치 있는가"를 알려준다.
**리스크:** "AR과 포인팅이 부수적이다" → 공간 정합 단서 vs 표 형태 제시를 대비시켜 AR을 부하 요소로 유지

### 4순위 — 사물이 아닌 사람을 선택하기
조사에서 **사람 대상 ray-casting 문헌을 찾지 못했다.** 군집한 신체 중 하나를 고르는 것, 엎드린/가려진 자세가 선택 성능에 미치는 영향. 표준 타겟 획득 모델의 가정(직립 바운딩 박스, 안정적 겉보기 크기)이 깨진다.
**리스크가 가장 큼** — "타겟 모양만 바꾼 Fitts 법칙". 표준 모델에서의 *이탈*을 보일 수 있을 때만 추진.

### 5순위 — 방법론/윤리 기여
비임상 응급도 추정 인터페이스의 평가 프로토콜. **단독 투고 금지**, 1순위 논문의 방법 절로 묶거나 워크숍용.
