# 01. 프로젝트 정의와 연구 범위

> 상위 문서: [`README.md`](../README.md) · 관련: [`03-strategic-judgment.md`](./03-strategic-judgment.md)

## 1. 한 줄 정의 (개발 단계)

Triage Trace는 재난 상황을 가정한 지하철 환경에서, 구조자가 웹캠 기반 팔 제스처로 대상을 가리키고 일정 시간 유지하여 확인 상태를 추적하는 **비의료적 시뮬레이션 프로토타입**이다.

## 2. 한 줄 정의 (연구 단계 — 이번 확장의 목표)

> 다수 대상 재난 시뮬레이션에서, **불완전한 응급도 추정 결과를 AR HUD가 어떻게 제시하느냐**가 사용자의 분류 정확도·과분류/저분류·탐색 시간·적정 의존에 미치는 영향을 측정한다.

두 정의의 차이가 이 폴더 전체의 존재 이유다. 전자는 시스템이고 후자는 연구다.

## 3. 무엇이 바뀌었나 — "응급도 판별" 요구의 재해석

원래 요구: *"의료까지는 아니더라도, 사람의 응급도를 판별할 수 있게 하고 싶다."*

이 요구는 **옳은 직관이지만 구현 위치가 잘못되어 있었다.**

| 착각 | 실제 |
|---|---|
| 시스템이 환자의 응급도를 추정한다 | 환자는 Unity 안의 가상 모델이다. 정답을 우리가 저작한다. 추정이 아니라 조회다 |
| 웹캠으로 응급도를 읽는다 | 웹캠은 **구조자**를 본다. 환자를 보지 않는다 |
| 정확한 추정기가 기여다 | 추정기의 정확도는 우리가 정하는 숫자다. 기여가 될 수 없다 |
| 의학 지식이 필요하다 | 라벨은 공개된 프로토콜 분기표의 기계적 적용이다 |

**재해석:** 응급도 추정의 *결과*는 연구의 입력이지 출력이 아니다. 우리가 통제하는 독립변수는 **추정의 정확도 수준**과 **그 불확실성의 표현 방식**이고, 종속변수는 **사용자의 판단 성능**이다.

이 재해석 덕분에 "가상 환자"가 한계에서 강점으로 바뀐다. 실제 시스템으로는 정확도를 85%와 70%로 마음대로 맞출 수 없지만, 시뮬레이션에서는 가능하다.

## 4. 연구 범위 경계

### 포함

- 제스처(또는 HMD 레이) 기반 대상 지정과 dwell 확인
- 방향·거리·확인 상태·**응급도 추정 결과**를 결합한 AR 스타일 정보 표현
- 추정 신뢰도 수준의 실험적 조작
- 불확실성 표현 방식(확정 라벨 / 신뢰도 등급 / 판단 보류)의 비교
- 다수 대상 탐색 순서와 상황 인식
- 데스크톱 시뮬레이션 및 (2단계) HoloLens 2 광학투과 조건

### 제외 — 논문에 절대 쓰지 않는다

- 실제 환자에 대한 응급도 분류 또는 의료 의사결정
- 실제 생체신호 추정(rPPG, 호흡수, SpO₂). 근거는 [`12-literature-landscape.md`](../10-research/12-literature-landscape.md) §1b
- 실제 환자 정보나 병원 시스템 연동
- 의료기기 인증 또는 임상 효능 주장
- 실제 재난 현장에서의 안전성·유효성

### 기존 저장소의 안전 경계 (그대로 유지)

`C:\Projects\MediapipeExample\AGENTS.md` §1이 이미 명시하고 있다:

> 이 프로젝트는 실제 환자를 평가하거나 분류하지 않는다. 진단, 치료, 응급도 판단, 의료 자문 또는 임상 의사결정을 제공하지 않으며, Unity 화면의 모든 분류·선택·상태는 가상의 시나리오를 위한 모의 인터페이스다.

응급도 단서를 추가해도 **이 문장은 수정하지 않는다.** 추가되는 것은 가상 시나리오의 속성이지 실제 판단 능력이 아니다. 단서 레이어 도입 시 `AGENTS.md`에 한 문단을 **덧붙이되** 위 경계 선언은 그대로 둔다.

## 5. 용어 통제

논문과 코드에서 일관되게 쓸 용어를 고정한다. 혼용하면 리뷰어가 의료 주장으로 읽는다.

| 쓸 것 | 쓰지 말 것 | 이유 |
|---|---|---|
| urgency cue / 응급도 단서 | symptom / 증상 | 증상은 임상 용어 |
| authored ground truth / 저작된 정답 | correct diagnosis / 정확한 진단 | 진단이 아님 |
| priority label / 우선순위 라벨 | triage category (단독 사용) | 프로토콜 인용 시에만 허용 |
| estimator confidence / 추정 신뢰도 | accuracy of our system | 우리 시스템의 정확도가 아니라 시뮬레이션된 값 |
| simulated assessment / 모의 평가 | assessment | 단독 사용 시 임상 평가로 읽힘 |
| participant / 참가자 | clinician, responder | 참가자는 의료인이 아님 |

기존 코드의 `PatientInteractionState`(Unseen/Highlighted/InProgress/Checked)는 **확인 흐름**이고, 새로 추가할 응급도 차원은 **직교하는 별개 enum**이다. 절대 하나로 합치지 않는다. 근거는 `PatientView.cs`의 기존 주석:

> Interaction colors must stay separate from triage severity colors such as red/yellow/green/black. These states track confirmation flow only; they are not medical classification.

이 설계 의도는 이미 코드에 있다. 확장 시 유지한다.
