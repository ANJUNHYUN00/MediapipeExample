# 23. Level 2 — 신뢰도 조작 + 불확실성 HUD 사양

> 이것이 **논문의 핵심 기여**다. 선행: [`22-instrumentation-spec.md`](./22-instrumentation-spec.md)

## 1. 신뢰도 조작

### 원리

`PatientUrgencyProfile`의 `truthLabel`에서 출발해, `scenarioSeed`와 `estimatorReliability`로 **결정론적으로** `estimatedLabel`을 생성한다.

```
estimatedLabel(patient) =
    truthLabel                              if not mislabeled(patient, seed, reliability)
    perturb(truthLabel, direction(seed))     otherwise
```

### 오라벨 규칙

| 신뢰도 | 10명 중 오라벨 수 | 방향 |
|---|---|---|
| R100 | 0 | — |
| R85 | 2 | 1 과추정 + 1 저추정 |
| R70 | 3 | 2 과추정 + 1 저추정 (또는 seed에 따라 1:2) |

- `perturb`는 **인접 등급으로만** 이동한다 (P2↔P1, P3↔P2). P3를 P1로 바꾸는 극단 오류는 넣지 않는다 — 너무 명백해서 조작이 드러난다
- **P4(예상)는 오라벨 대상에서 제외**
- 저추정(P1→P2) 오라벨이 **매 조건마다 최소 1건** 보장되어야 한다. 안전 임계 지표의 분모다

### 논문에서의 정당화

> 시뮬레이션된 추정 정확도 수준은 임의로 정한 값이 아니라, 보고된 standoff 트리아지 시스템의 성능 범위에서 가져왔다: 반자동 UAS 트리아지 89%, 드론 기반 옥외 호흡수 82.8%, 다중센서 standoff 운동성 분류 15명 중 10명. 100% 조건은 상한 기준선이자 조작 점검으로 포함하였다.

## 2. 불확실성 표현 3조건

세 조건 모두 **동일한 추정 결과**를 받는다. 다른 것은 제시 방식뿐이다.

### 조건 A — 확정 라벨 (HardLabel)

월드 카드:
```
┌──────────────────┐
│ TR-003           │
│ ▌ P1  IMMEDIATE  │   ← 색 + 문자 이중 부호화
│ SIMULATION ONLY  │
└──────────────────┘
```
- 단일 라벨만. 불확실성 정보 없음
- 자동화 편향이 가장 크게 나타날 것으로 예상되는 조건 (H1)

### 조건 B — 신뢰도 등급 (GradedConfidence)

```
┌──────────────────┐
│ TR-003           │
│ ▌ P1  IMMEDIATE  │
│ CONFIDENCE ●●○   │   ← 3단계
│ alt: P2 DELAYED  │   ← 차순위 후보
│ SIMULATION ONLY  │
└──────────────────┘
```
- 신뢰도 3단계(높음/보통/낮음)를 점 3개로 표현
- 차순위 후보 라벨 1개 병기
- **신뢰도 값은 실제 오라벨 여부와 상관관계를 가져야 한다.** 오라벨 대상의 70%는 낮은 신뢰도로 표시한다 (완벽한 상관은 비현실적)

⚠️ 여기가 설계의 미묘한 지점이다. 신뢰도가 오라벨과 **무상관**이면 참가자가 무시하는 게 합리적이 되어 조건이 무의미해진다. **상관을 갖되 완전하지 않게** 만든다. 이 값(0.7)을 논문에 명시한다.

### 조건 C — 판단 보류 (AbstainDefer)

```
┌──────────────────┐
│ TR-003           │
│ ▌ UNCERTAIN      │   ← 라벨 대신 보류
│ CHECK DIRECTLY   │
│ cues: no motion, │
│       supine     │
│ SIMULATION ONLY  │
└──────────────────┘
```
- 신뢰도가 임계 미만이면 **라벨을 제시하지 않고** 직접 확인을 요구
- 임계 이상이면 조건 A와 동일하게 표시
- 보류 비율은 신뢰도 수준에 연동: R85에서 약 20%, R70에서 약 35%가 보류

⚠️ **보류 임계를 실제 오라벨과 맞추면 안 된다.** 완벽한 보류는 정확도 100%를 만들어 조건 비교가 무너진다. 보류 대상의 일부는 실제로 맞은 추정이어야 하고(불필요한 보류), 오라벨 일부는 보류되지 않아야 한다(놓친 보류).

## 3. HUD 측 표시

`ARGuidanceHud`의 `NEARBY PATIENTS` 패널에 추정 라벨을 추가한다.

```
NEARBY PATIENTS
TR-003  ▌P1  4.2m   ●●○
TR-007  ▌P2  6.8m   ●●●
TR-001  ▌??  8.1m   ---     ← 보류 조건
TR-009  ▌P3  11.3m  ●○○
```

조건별 차이:
- A: 라벨만, 신뢰도 열 없음
- B: 라벨 + 신뢰도 점
- C: 보류 대상은 `??`

**계약 유지:** HUD는 여전히 읽기 전용이다. `PatientUrgencyProfile`과 `ExperimentRunner`의 상태를 구독할 뿐, 어떤 판정도 수행하지 않는다.

## 4. 색 + 문자 이중 부호화

색만으로 라벨을 구분하지 않는다. 이유 3가지:
1. 색각 이상 참가자를 제외하지 않아도 된다
2. 접근성 측면에서 리뷰어에게 긍정적
3. HL2의 가산 도파관 디스플레이에서는 색 재현이 제한적 — 2단계를 대비한 설계

| 라벨 | 색 | 문자 | 막대 |
|---|---|---|---|
| Immediate | 적 | `P1` | ▌▌▌▌ |
| Delayed | 황 | `P2` | ▌▌▌ |
| Minor | 녹 | `P3` | ▌▌ |
| Expectant | 회/흑 | `P4` | ▌ |

⚠️ HL2의 가산 디스플레이에서 **검정은 투명**이다. P4를 흑색으로 쓰면 2단계에서 보이지 않는다. 회색 + 빗금 패턴으로 대체할 것.

## 6. 수용 기준

- [ ] 동일 seed + 동일 reliability → 오라벨 배치가 항상 동일
- [ ] R100에서 오라벨이 0건
- [ ] 모든 조건에서 저추정 오라벨이 최소 1건
- [ ] P4가 오라벨 대상이 되지 않음
- [ ] 조건 B의 신뢰도–오라벨 상관이 설계값(0.7) 근처
- [ ] 조건 C에서 불필요한 보류와 놓친 보류가 모두 존재
- [ ] 세 조건의 카드가 **동일한 물리적 크기**를 차지 (시야 점유 교란 방지)
- [ ] 색각 시뮬레이터로 확인 — 색 없이도 라벨 판독 가능
- [ ] HUD가 입력에 전혀 관여하지 않음 (기존 계약)
- [ ] 9조합 모두 실제로 실행되어 스크린샷이 남아 있음

## 7. 파일럿에서 검증할 설계 가정

| 가정 | 검증 방법 | 실패 시 |
|---|---|---|
| 참가자가 신뢰도 점을 인지하고 사용한다 | 조건 B의 오라벨 검출률 > 조건 A | 시각적 현저성 강화 |
| 보류가 재검토를 유발한다 | 조건 C의 대상당 시간 > A | 보류 문구 강화 |
| 오라벨이 검출 가능하다 | 전 조건 검출률 > 0 | 단서 판독성 문제 — 애니메이션 개선 |
| 세 조건의 카드 크기가 체감상 동일 | 참가자 보고 | 레이아웃 조정 |
