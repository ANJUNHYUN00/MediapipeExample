# 13. 실험 설계

> RQ·가설: [`11-research-questions.md`](./11-research-questions.md) · 구현: [`22`](../20-engineering/22-instrumentation-spec.md), [`23`](../20-engineering/23-uncertainty-hud-spec.md)

## 1. 설계 개요

**3 × 3 요인 within-subject 설계** — 단, 전체 9조건은 학부 규모에서 과부하다. 아래 §2의 축소안을 기본으로 한다.

| 요인 | 수준 |
|---|---|
| A. 추정 신뢰도 | 100% / 85% / 70% |
| B. 불확실성 표현 | 확정 라벨 / 신뢰도 등급 / 판단 보류 |

## 2. 실제 실행 설계 (축소안)

전체 9조건 × 10명 환자 = 참가자당 90회 시행. 세션이 90분을 넘어가 피로 교란이 생긴다. 따라서:

### 주 설계: 혼합 설계

| 요인 | 배치 | 수준 |
|---|---|---|
| A. 신뢰도 | **참가자 간 (between)** | 85% 또는 70% 중 하나에 무작위 배정 |
| B. 표현 | **참가자 내 (within)** | 3수준 전부, 순서 라틴방격 |

- 참가자당 **3 블록 × 10명 = 30회 시행**. 세션 약 50~60분
- 100% 조건은 **모든 참가자가 연습 블록으로** 경험한다 (H4 조작 점검 겸 학습)
- N=24면 신뢰도 조건당 12명, 각 12명이 표현 3조건을 모두 경험

### 베이스라인 조건 (선택)

여력이 되면 **HUD 추정 없음(사용자가 단서만 보고 판단)** 조건을 연습 후 1블록 추가. 추정 자체의 순효과를 보여준다. 시간 예산상 파일럿 결과를 보고 결정.

## 3. 참가자

| 항목 | 값 |
|---|---|
| 목표 N | **24명** (최소 16명) |
| 파일럿 N | 5~8명 (본 실험 미포함) |
| 모집 | 일반 성인, 의료 전공 무관 |
| 제외 | 교정시력으로 화면 판독 불가, 색각 이상(라벨 색 구분 필요) |
| 기록할 개인 특성 | 연령대, 성별, 게임/XR 경험, 안경 착용, 색각 자가보고 |
| 데스크톱 단계 추가 기록 | 키, 팔 길이, 카메라 높이, 조명 조건 (MediaPipe 추적 품질 교란 통제) |
| 보상 | 기관 기준에 따름 |

⚠️ 색각 이상 제외는 라벨을 색으로만 구분할 때만 필요하다. **색 + 문자(P1/P2/P3/P4) 이중 부호화**를 쓰면 제외 기준을 없앨 수 있고 접근성 측면에서도 낫다. **이중 부호화를 채택한다.**

## 4. 과업

### 참가자에게 주는 지시 (한국어 원문)

> 당신은 지하철 재난 현장을 점검하는 대원입니다. 현장에는 10명이 있습니다. 화면의 보조 시스템이 각 사람의 대응 우선순위를 추정해 알려주지만, **이 추정은 완벽하지 않습니다.** 당신은 각 사람을 직접 확인하고, 최종 우선순위를 스스로 판단해 지정해야 합니다. 가능한 한 빠르고 정확하게 10명 전원을 처리하십시오.

핵심: **추정이 불완전하다는 사실을 명시적으로 고지한다.** 고지하지 않으면 자동화 편향이 아니라 단순 지시 따르기가 된다.

### 시행 절차 (1명당)

1. 참가자가 대상을 가리킨다 (제스처 레이 / HL2 단계에서는 hand ray)
2. 0.7초 dwell → 대상 선택, 월드 카드 표시
3. 카드에 **단서(자세·움직임·호흡 표시·반응성)** 와 **추정 결과**가 표시된다
4. 참가자가 최종 우선순위를 입력 (P1~P4) — 입력 방식은 §5
5. 다음 대상으로

### 최종 판단 입력 방식

데스크톱: 숫자키 1~4. HL2: 4방향 손 제스처 또는 음성 명령.

⚠️ 입력 방식이 조건 간 동일해야 한다. 입력 시간이 종속변수를 오염시키지 않도록 **판단 입력 시각과 dwell 완료 시각을 분리 기록**한다.

## 5. 종속변수

### 주 지표

| 지표 | 정의 | 비고 |
|---|---|---|
| **분류 정확도** | 참가자 최종 라벨 == 저작된 정답 라벨의 비율 | 주 종점 |
| **과분류율** | 정답보다 높은 우선순위로 지정한 비율 | 분리 보고 |
| **저분류율** | 정답보다 낮은 우선순위로 지정한 비율 | **안전 임계 — 분리 보고 필수** |

| **오라벨 추종률** | 추정이 틀린 시행 중, 참가자가 추정을 그대로 따른 비율 | 자동화 편향 |
| **대상당 시간** | dwell 완료 → 최종 판단 입력 | |
| **전체 완료 시간** | 블록 시작 → 10번째 판단 입력 | |

## 6. 조작 점검

| 점검 | 방법 | 통과 기준 |
|---|---|---|
| 신뢰도 조작 인지 | "추정이 대략 몇 %나 맞았다고 느꼈나?" | 85% 군 > 70% 군 (방향성) |
| 표현 조작 인지 | 각 조건 후 표현 방식을 객관식으로 회상 | 90% 이상 정답 |
| H4 (100% 조건 무차별) | 연습 블록 데이터 | 표현 간 정확도 차 유의하지 않음 |

## 7. 오라벨 배치 설계

이 부분이 실험의 심장이다. 대충 하면 결과가 무의미해진다.

- 85% 조건: 10명 중 **1~2명** 오라벨. 70% 조건: **3명** 오라벨
- **오라벨의 방향을 통제한다.** 절반은 과추정(P2를 P1로), 절반은 저추정(P1을 P2로). 저추정 오라벨이 안전 임계이므로 최소 1명은 반드시 포함
- 오라벨 대상의 위치·ID는 시나리오 세트마다 재배치
- **P4(예상)는 오라벨 대상으로 쓰지 않는다** — 윤리적으로 민감하고 해석이 복잡해진다
- 오라벨 여부는 `scenarioSeed`로 결정되며 로그에 기록된다

## 8. 절차

| 단계 | 시간 | 내용 |
|---|---|---|
| 1 | 5분 | 동의, 개인정보 고지, 인구통계 설문 |
| 2 | 10분 | 시스템 소개, 제스처 조작 연습 (환자 없는 씬) |
| 3 | 8분 | **연습 블록** — 신뢰도 100%, 표현 3종 순환, 환자 4명 |
| 4 | 15분 | 블록 1 (표현 조건 A) + NASA-TLX + SUS |
| 5 | 15분 | 블록 2 (표현 조건 B) + 설문 |
| 6 | 15분 | 블록 3 (표현 조건 C) + 설문 |
| 7 | 10분 | 사후 인터뷰, 디브리핑 |
| **계** | **~78분** | 블록 사이 2분 휴식 포함 |

블록마다 다른 시나리오 세트를 쓰고, 세트–블록 대응은 참가자 간 균형화한다.

## 9. 분석 계획 (사전 확정)

사후에 정하면 p-hacking이다. 분석 전에 이 절을 고정하고 변경 시 이력을 남긴다.

### 주 분석

- **분류 정확도**: 혼합 효과 로지스틱 회귀. 고정효과 = 표현(within) × 신뢰도(between), 랜덤효과 = 참가자 절편 + 환자 절편
- 정규성/등분산 가정이 깨지면 정확도를 참가자별 비율로 집계 후 **Friedman + Wilcoxon 사후**(Holm 보정)
- **과분류·저분류**: 각각 별도 모형. 합쳐서 보고하지 않는다
- **대상당 시간**: 로그 변환 후 repeated measures ANOVA, Greenhouse-Geisser 보정
- **오라벨 검출률**: 오라벨 시행만 대상으로 혼합 효과 로지스틱

### 보고 규칙

- 효과 크기와 95% 신뢰구간을 **항상 함께** 보고 (Cohen's d 또는 odds ratio)
- 다중비교 보정: Holm–Bonferroni
- 유의하지 않은 결과도 효과 크기와 CI로 보고한다
- 제외된 참가자와 사유를 전부 명시

### 정성 분석

사후 인터뷰를 주제별 코딩. 초기 코드북: 조작 부담 / 오인식 / 추정 불신 / HUD 정보 과부하 / 시야 방해 / 공간 혼란 / 판단 근거. 2인 코딩 후 일치도 보고가 이상적이나, 1인이면 그 사실을 명시한다.

## 10. 파일럿에서 확인할 것

- [ ] 세션 총 시간이 80분을 넘는가 → 넘으면 블록당 환자 수 축소
- [ ] 0.7초 dwell이 과업 리듬과 맞는가
- [ ] 단서 애니메이션이 원거리에서 판독되는가
- [ ] 추정 불완전 고지가 실제로 참가자 행동을 바꾸는가 (오라벨 검출률 > 0인가)
- [ ] SAGAT 프로브가 몰입을 지나치게 깨지 않는가
- [ ] 판단 입력(숫자키)이 제스처 조작과 충돌하지 않는가
- [ ] 환자 모델/마커/카드가 raycast를 가리는가
- [ ] P4 환자에 대한 정서 반응 — 제외 여부 결정
- [ ] Python 프리뷰 창이 참가자 화면을 가리지 않는가
- [ ] 로그 파일이 모든 시행을 빠짐없이 기록하는가 (**가장 중요**)

## 11. HoloLens 2 단계의 변경점 (2027-02~03)

| 항목 | 데스크톱 | HoloLens 2 |
|---|---|---|
| 포인팅 | MediaPipe 팔 레이 | hand ray (또는 eye gaze 조건 추가) |
| FOV | 화면 전체 | **52° 대각 — 실제 제약** |
| 판단 입력 | 숫자키 | 손 제스처 또는 음성 |
| 추가 제외 | — | 시선 캘리브레이션 실패 |
| 추가 측정 | — | 머리 회전량, 시선 체류 |
| 추가 설문 | — | SSQ (시뮬레이터 멀미) |

**시선 캘리브레이션 실패는 실질적 제외 사유다.** 안경·콘택트·눈 수술 이력·강한 조명에서 실패한다. 파일럿에서 5명 먼저 돌려 실패율을 확인하고, 제외 규칙과 head-gaze 폴백을 사전 등록한다.
