# Unity 공간 구현 및 1인칭 시점 방법론

## 목적과 적용 범위

이 문서는 Triage Trace Unity 시뮬레이션에서 공간, 카메라, 이동과 AR 상호작용을 일관되게 설계하기 위한 일반 방법론이다. 실제 의료 환경이나 실제 환자 흐름을 재현하거나 평가하지 않으며, 모든 공간과 상호작용은 비의료 교육·시연용 가상 시나리오에 한정한다.

## 1. 공간을 먼저 경로로 정의한다

구현 전에 다음을 짧게 문서화한다.

- 목적: 사용자가 공간에서 수행하거나 확인할 비의료 시나리오 목표
- 시작점: Spawn 위치, 초기 방향, 처음 보이는 안내 요소
- 이동 경로: 시작점에서 종료점까지의 주 경로와 방향 전환 지점
- 필수 구역: 사용자가 접근·관찰·상호작용해야 하는 구역
- 종료점: 시나리오 완료 또는 데모 종료를 확인할 위치와 상태

이 정의는 배경 장식보다 먼저 검토한다. 1인칭 시점에서는 시야, 이동 폭, 장애물, 목표가 순서대로 이해되는지가 핵심이다.

## 2. Unity 구성 요소로 번역한다

공간 정의를 다음 책임 단위로 옮긴다.

| 공간 결정 | Unity 구현 대상 |
|---|---|
| 구역과 배경 | Hierarchy의 환경 루트, 검증된 모듈형 Prefab |
| 통과 가능·불가능 경계 | Collider와 Layer 규칙 |
| 시작점 | Spawn Transform과 초기 방향 |
| 시야와 조준 | 단일 활성 `Main Camera`, 카메라 규칙 |
| 상호작용 대상 | Patient Prefab, Collider, 상호작용 Layer |

배경은 우선 검증된 모듈형 에셋을 조합한다. 새 메시, 복잡한 셰이더 또는 자동 생성 배경은 경로·충돌·카메라 검증을 통과한 뒤에만 추가한다.

## 3. 책임 경계를 유지한다

- 환경은 지형, 배경, 조명, 경로와 충돌 경계를 담당한다.
- 플레이어 이동은 입력 해석과 이동·충돌 반응을 담당한다.
- 카메라는 시점과 화면 투영을 담당하며, 활성 `Main Camera`는 하나만 둔다.
- AR 인터랙션은 검증된 pose pointer 방향을 사용해 raycast, hover, dwell, Patient 상태와 카드 표시를 담당한다.

공간·카메라 작업은 Python Pose 처리, `pose_pointer` v2 WebSocket 계약, Unity raycast 방향 또는 dwell 규칙을 변경하지 않는다. 변경이 필요하면 별도 계약 변경 작업으로 분리한다.

## 4. 씬과 자동화의 안전한 운영

제작용 `TriageTraceDemoScene`은 수동 검증의 기준 씬이다. 외부 도구나 자동 생성 스크립트가 이 씬을 덮어쓰지 않게 하고, 실험은 이름이 구분된 별도 테스트 씬에서 한다. 런타임에 누락된 보조 오브젝트를 보완하는 기존 bootstrap 동작은 제작 씬 파일을 재생성하는 도구와 구분해 검토한다.

Unity 씬 YAML은 병합 충돌과 참조 손상 위험이 크므로 한 시점에 한 명의 작업자 또는 에이전트만 같은 씬 파일을 수정한다.

## 5. 작업 문서와 검증

공간 관련 Plan 또는 Task에는 다음을 명시한다.

- 수정 범위와 제외 범위
- 공간 경로와 관련 Hierarchy·Prefab·Collider·Spawn·Camera 변경점
- 완료 기준
- 검증 방법과 미확인 위험

Play Mode에서는 최소한 시작점과 이동 경로, 충돌 경계, pose pointer 기반 Patient 선택, 선택 뒤 상태 카드 표시를 확인한다. 이 프로젝트는 포즈 기반 AR 시뮬레이션이므로, 이동 검증은 별도의 1인칭 이동 시스템 추가를 요구하지 않는다. 현재 구현에 이동 기능이 없다면 해당 항목을 적용 범위 밖 또는 수동 카메라 탐색으로 명시한다.
