# MediaPipe–Unity 가위바위보 손 인식 앱 기획서

## 1. 프로젝트 개요

웹캠 영상을 MediaPipe로 분석해 사용자의 손을 인식하고, 손 모양을 `주먹(Rock)`, `가위(Scissors)`, `보(Paper)` 중 하나로 판정한다. 판정 결과와 필요한 손 정보를 WebSocket으로 Unity에 실시간 전송하고, Unity 앱 화면에 연결 상태와 인식 결과를 표시한다.

## 2. 목표

- 웹캠에서 손을 실시간으로 검출한다.
- 21개 손 랜드마크를 이용해 주먹, 가위, 보를 판정한다.
- 판정 결과를 WebSocket JSON 메시지로 Unity에 전송한다.
- Unity에서 연결 상태와 현재 손 모양을 직관적으로 표시한다.
- 손이 없거나 판정이 불확실한 상태를 정상적으로 처리한다.
- 인식 로직, 통신 로직, Unity 표시 로직을 분리해 유지보수와 확장이 쉽도록 구성한다.

## 3. 범위

### 포함 범위

- 한 명의 한 손 인식
- 주먹, 가위, 보 및 미인식 상태 판정
- 로컬 PC의 MediaPipe와 Unity 간 WebSocket 통신
- Unity 실시간 결과 UI
- 연결 끊김 및 재연결 처리
- 기본 로그와 테스트 절차

### 초기 버전 제외 범위

- 두 명 이상 동시 대전
- 온라인 서버를 통한 원격 대전
- 사용자 계정, 전적, 랭킹
- 모바일 빌드 최적화
- 머신러닝 모델을 별도로 학습하는 커스텀 제스처 분류

## 4. 사용자 시나리오

1. 사용자가 MediaPipe 프로그램을 실행한다.
2. 프로그램이 웹캠을 열고 WebSocket 서버를 시작한다.
3. 사용자가 Unity 앱을 실행한다.
4. Unity가 WebSocket 서버에 연결한다.
5. 사용자가 카메라 앞에서 주먹, 가위 또는 보를 낸다.
6. MediaPipe가 손 랜드마크를 추출하고 손 모양을 판정한다.
7. Unity가 받은 결과를 텍스트와 이미지 또는 애니메이션으로 표시한다.
8. 손이 화면에서 사라지면 Unity는 `손을 인식할 수 없음` 상태를 표시한다.

## 5. 시스템 구성

```text
[Webcam]
    |
    v
[Python / MediaPipe]
  - 영상 캡처
  - 손 랜드마크 검출
  - 제스처 판정
  - 결과 안정화
  - WebSocket Server
    |
    | JSON over ws://127.0.0.1:8765
    v
[Unity / WebSocket Client]
  - 메시지 수신 및 역직렬화
  - 메인 스레드 전달
  - 연결 상태 관리
  - 결과 UI 표시
```

| `MediapipeUnity` | Unity 프로젝트, WebSocket 수신, 결과 모델, UI 표시 |

## 6. 기술 스택

### MediaPipe 애플리케이션

- Python 3.11 권장
- OpenCV: 웹캠 캡처와 디버그 화면
- MediaPipe Hand Landmarker 또는 Hands: 21개 손 랜드마크 검출
- `websockets`: 비동기 WebSocket 서버
- `pytest`: 판정 및 메시지 생성 로직 테스트

### Unity 애플리케이션

- Unity LTS 버전
- C#
- TextMeshPro: 결과 텍스트 표시
- Unity 호환 WebSocket 라이브러리
- `JsonUtility` 또는 호환 JSON 역직렬화 도구

Unity용 WebSocket 라이브러리는 대상 플랫폼과 Unity 버전을 확정한 뒤 선택한다. 데스크톱 우선 버전에서는 연결 종료, 예외 처리, 백그라운드 수신 및 메인 스레드 전달을 지원해야 한다.

## 7. 손 인식 및 판정 설계

### 입력 데이터

MediaPipe가 반환하는 한 손의 21개 정규화 랜드마크를 사용한다. 각 랜드마크는 `x`, `y`, `z` 값을 가지며, 좌우 손 정보(`Left`, `Right`)와 검출 신뢰도를 함께 활용한다.

### 손가락 펼침 판정

- 검지, 중지, 약지, 소지: 손가락 끝과 관절의 상대 위치 및 손가락 진행 방향으로 펼침 여부를 계산한다.
- 엄지: 좌우 손에 따른 방향 차이를 보정하고 엄지 끝, 관절, 손바닥 기준점의 상대 위치 또는 관절 각도를 이용한다.
- 카메라 회전과 손 기울기에 덜 민감하도록 단순 화면 `y` 좌표 비교만 사용하지 않고, 관절 벡터 또는 각도 기반 판정을 우선한다.

### 가위바위보 규칙

| 결과 | 기본 판정 조건 |
|---|---|
| `ROCK` | 검지, 중지, 약지, 소지가 모두 접힘 |
| `SCISSORS` | 검지와 중지가 펼쳐지고 약지와 소지가 접힘 |
| `PAPER` | 검지, 중지, 약지, 소지가 모두 펼쳐짐 |
| `UNKNOWN` | 위 조건에 해당하지 않거나 신뢰도가 낮음 |
| `NO_HAND` | 손이 검출되지 않음 |

엄지 상태는 보조 특징으로 활용한다. 다양한 주먹과 가위 자세를 허용하기 위해 초기 규칙에서는 엄지만으로 결과를 배제하지 않는다.

### 결과 안정화

프레임마다 결과가 흔들리는 문제를 줄이기 위해 최근 프레임의 결과를 버퍼에 저장한다.

- 최근 5~10개 프레임에서 다수결 적용
- 동일 결과가 설정된 최소 횟수 이상일 때만 확정
- 불확실한 결과는 `UNKNOWN` 처리
- 손 미검출이 일정 프레임 이상 이어질 때 `NO_HAND` 전송
- 동일한 확정 결과는 전송 주기를 제한하거나 상태 변경 시 우선 전송

구체적인 임계값은 조명, 카메라 거리, 손 방향을 달리한 테스트 결과를 바탕으로 조정한다.

## 8. WebSocket 통신 설계

### 연결

- 기본 주소: `ws://127.0.0.1:8765`
- MediaPipe: WebSocket 서버
- Unity: WebSocket 클라이언트
- 기본 송신 빈도: 초당 10~20회 이하
- Unity는 연결 실패 또는 종료 시 일정 간격으로 재연결을 시도한다.

### 메시지 형식

```json
{
  "type": "hand_gesture",
  "version": 1,
  "timestamp": 1750000000123,
  "sequence": 42,
  "handDetected": true,
  "handedness": "Right",
  "gesture": "SCISSORS",
  "confidence": 0.94,
  "fingerStates": {
    "thumb": true,
    "index": true,
    "middle": true,
    "ring": false,
    "pinky": false
  }
}
```

### 필드 정의

| 필드 | 형식 | 설명 |
|---|---|---|
| `type` | string | 메시지 종류. 초기 버전은 `hand_gesture` |
| `version` | integer | 메시지 스키마 버전 |
| `timestamp` | integer | Unix epoch 기준 밀리초 |
| `sequence` | integer | 전송 순서 확인용 증가 번호 |
| `handDetected` | boolean | 손 검출 여부 |
| `handedness` | string | `Left`, `Right`, `Unknown` |
| `gesture` | string | `ROCK`, `SCISSORS`, `PAPER`, `UNKNOWN`, `NO_HAND` |
| `confidence` | number | 0.0~1.0 범위의 판정 신뢰도 |
| `fingerStates` | object | 각 손가락의 펼침 여부 |

손이 검출되지 않은 경우 `handDetected`는 `false`, `gesture`는 `NO_HAND`, `confidence`는 `0.0`으로 보낸다. Unity는 알 수 없는 필드를 무시해 이후 스키마 확장을 허용한다.

## 9. Unity 화면 설계

### 필수 UI

- 앱 제목
- WebSocket 연결 상태: 연결 중, 연결됨, 연결 끊김
- 현재 결과: 주먹, 가위, 보, 미인식
- 결과별 이미지 또는 아이콘
- 신뢰도 표시
- 선택 사항: 좌우 손 정보와 마지막 수신 시각

### 표시 규칙

| 수신 값 | 화면 표시 |
|---|---|
| `ROCK` | `주먹`과 주먹 이미지 |
| `SCISSORS` | `가위`와 가위 이미지 |
| `PAPER` | `보`와 보 이미지 |
| `UNKNOWN` | `손 모양을 확인해 주세요` |
| `NO_HAND` | `손을 카메라에 보여 주세요` |
| 연결 끊김 | 마지막 결과를 비활성화하고 연결 오류 표시 |

WebSocket 콜백은 Unity의 메인 스레드가 아닐 수 있으므로, 수신 메시지를 스레드 안전 큐에 넣고 `Update()`에서 꺼내 UI를 변경한다.

## 10. 비기능 요구사항

- 일반적인 개발용 PC에서 사용자에게 자연스럽게 느껴지는 실시간 반응을 제공한다.
- 카메라 영상은 기본적으로 로컬에서만 처리하고 저장하거나 네트워크 외부로 전송하지 않는다.
- 잘못된 JSON, 연결 종료, 카메라 열기 실패가 앱 전체 종료로 이어지지 않도록 한다.
- 설정값은 코드에 흩어놓지 않고 포트, 카메라 번호, 임계값 등으로 분리한다.
- 로그에는 연결 상태, 카메라 상태, 판정 결과 변경, 예외 원인을 기록한다.

- 메인 스레드 메시지 전달 구현
- 결과 UI 및 상태별 표시 구현

### 4단계: 통합 및 개선

- MediaPipe와 Unity 통합 테스트

- 실행 방법 및 문제 해결 문서화

## 12. 테스트 계획

### 기능 테스트

- 정면과 좌우 손으로 각 제스처가 올바르게 판정되는지 확인
- 손이 없을 때 `NO_HAND`가 표시되는지 확인
- 규칙에 없는 손 모양이 `UNKNOWN`으로 처리되는지 확인
- Unity가 모든 메시지 값을 올바른 한글 결과로 표시하는지 확인
- MediaPipe를 먼저 또는 나중에 실행해도 연결되는지 확인
- 서버 종료 후 Unity가 연결 끊김을 표시하고 재연결하는지 확인

### 환경 테스트

- 밝은 환경과 어두운 환경
- 단색 배경과 복잡한 배경
- 카메라와 가까운 손 및 먼 손
- 손바닥과 손등
- 손이 기울거나 일부 회전한 상태

### 성능 확인 항목

- 카메라 처리 FPS
- 검출부터 Unity 표시까지의 평균 지연 시간
- 초당 WebSocket 메시지 수
- 장시간 실행 시 메모리 및 연결 안정성
